## `twins/` — counterfactual twin generator

Design and reasoning: `docs/research/counterfactual-twins.md`.

| File | What it does |
|---|---|
| `twins/airline_policy.py` | The airline policy as code (cancellation, cancelled- and delayed-flight certificates), with switchable rules for policy flips. The tools do not enforce policy, so the generator uses this oracle. |
| `twins/policy_flips.yaml` | One-sentence policy edits: the exact sentence, its replacement, the oracle rule it toggles. |
| `twins/specs/airline.yaml` | One short spec per no-action task: the blocked write, the reason, the facts the script locks, the preferred flip. Lists the excluded tasks and why. |
| `twins/generate.py` | Searches one-field DB flips, applies policy flips, builds the twin tasks, validates them with the tau2 evaluator, writes `tasks_twins.json` and its split. |
| `twins/score_pairs.py` | Pair scoring: a no-action pass counts only if the twin also passes. Reports twin failure causes. |

Run from `code/tau2-bench/`:

```bash
uv run python ../twins/generate.py              # regenerate and validate the twins
uv run tau2 run --domain airline --task-set-name airline_twins --task-split-name primary \
  --agent-llm ... --save-to airline_twins_<model>
uv run tau2 run --domain airline_pf_delay_no_change --task-set-name airline_twins \
  --task-split-name pf_delay_no_change --agent-llm ... --save-to airline_twins_pf_<model>
uv run python ../twins/score_pairs.py claude-sonnet-4.5 gpt-4.1   # needs airline_<model> runs too
```

## Run the baselines

All commands run from `code/tau2-bench/`. Results go to `data/simulations/<save-to>/` and are
tracked in git.

**Null agent** (free, no LLM):

```bash
uv run tau2 run --domain airline --agent do_nothing_agent --user scripted_user \
  --num-trials 1 --save-to airline_do_nothing
```

**A model through Prime Intellect.** LiteLLM needs the `openai/` prefix in front of the Prime
Intellect model ID, so `openai/gpt-4.1` becomes `openai/openai/gpt-4.1`.

```bash
set -a; source .env; set +a
ARGS="{\"api_base\": \"$PI_API_BASE\", \"api_key\": \"$PI_KEY\", \"temperature\": 0}"
uv run tau2 run --domain airline \
  --agent-llm openai/openai/gpt-4.1 --agent-llm-args "$ARGS" \
  --user-llm  openai/openai/gpt-4.1 --user-llm-args  "$ARGS" \
  --num-trials 1 --save-to airline_gpt41_check
```

**Alternative: keep the key out of `llm_args`.** Put the key in the process environment.
LiteLLM reads it there, and tau2 never sees it. The five-model runs (`docs/research/findings-log.md` §7)
used this method:

```bash
set -a; source .env; set +a
export OPENAI_API_KEY="$PI_KEY" OPENAI_API_BASE="$PI_API_BASE"
uv run tau2 run --domain airline \
  --agent-llm openai/anthropic/claude-sonnet-4.5 --agent-llm-args '{"temperature": 0.0}' \
  --user-llm  openai/openai/gpt-4.1 --user-llm-args '{"temperature": 0.0}' \
  --num-trials 1 --seed 300 --max-concurrency 5 --save-to airline_claude-sonnet-4.5
```

To add tasks to an existing run, run again with the same `--save-to` and `--auto-resume`.
Completed tasks are skipped.

The key is redacted in the saved results. Check anyway before you commit:
`git diff --cached | grep -E 'pit_|sk-'` must print nothing.

Then add an entry to `docs/research/findings-log.md`.

## Scoring modes (COS597C justification check)

Justified scoring is the default: on a no-action task listed in
`data/tau2/domains/<domain>/justification.json`, a pass becomes 0 when a required read is
missing. Add `--original-scoring` to `tau2 run` or `tau2 evaluate-trajs` for upstream scoring.
Every result saves both `reward` and `original_reward`, plus `scoring_mode` and the per-read
`justification`. Method: `docs/research/justification-check.md`.

```bash
uv run tau2 evaluate-trajs data/simulations/<run>/results.json --fresh-tasks -o data/simulations/<run>_justified
uv run pytest tests/test_justification.py -q
```
